# Contribution

## Avant toute modification
Lire le cahier des charges, l’architecture et les règles de sécurité.

## Commits
Utiliser des messages courts et explicites.

## Pull requests
Décrire le besoin, la modification, les tests et les éventuels impacts de sécurité.

## Données
Ne jamais commiter de secrets, tokens ou données personnelles réelles.

## Documentation
Toute décision importante doit être documentée.
